# Data area

No TMDB credentials, downloaded movie dataset or artwork is bundled. Real ingestion checkpoints and published records are stored in your PostgreSQL database, not committed as bulk JSON. Follow [Phase 4 ingestion](../docs/phase-04/ingestion.md).

`reviews.example.json` is an empty review-file template. Copy it to `reviews.local.json`, add evidence-backed decisions using actual source IDs from your report, and pass the same file to review and publish. Local reviews are ignored by git and excluded from distributed ZIPs.

Phase 3 demo records in backend/app/fixtures.py and Phase 4 test responses in backend/tests/tmdb_fixtures.py are explicitly synthetic. Tests use the fixture namespace; their provider-shaped numeric IDs are not asserted to be real TMDB identities. Load demo records only with the opt-in seed command after migrations.

Phase 5 adds `phase5-calibration.json`, generated by `python -m scripts.talent_example`. Every input is explicitly synthetic; the file contains no downloaded TMDB records or credentials. The example runs without a database and does not publish records.

Phase 6 adds the synthetic `phase6-graph-example.json`. Phase 7 adds `phase7-assignment-example.json`, generated by `python -m scripts.assignment_example`; its invented person IDs and fees illustrate the difference between independent role minima and a feasible distinct-person assignment. Neither file is imported TMDB data.

Phase 8 adds `phase8-simulation-example.json`, generated by `python -m scripts.simulation_example`. Every person, fee and feature is invented for arithmetic/replay exercises. The output includes three deterministic draws, full-precision components, integer-dollar financials and hashes. It is not a published catalog or a forecast of a real film.
