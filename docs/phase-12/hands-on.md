# Four exercises in VS Code

**1. Verify a KPI.** Generate the `demo` sample using the root README. Open its `dashboard.html`. Under “Trace a dashboard number,” inspect a released row and an unfinished row. Run `audit_demo.py` on the generated SQLite database. Count the distinct start keys and nonempty official release keys yourself: 12 and 7. Empty release evidence is not evidence of abandonment; check the explicit abandon event in the dashboard’s stop table.

**2. Change the population.** Keep `--as-of 2026-11-01`. A demo report filtered to `--genre thriller` has 6 starts and 3 releases. Add `--from 2026-10-02 --until 2026-10-03` to select just one thriller start. Choose a catalog absent from the sample: the report should have zero starts and no measured rates. Open the `versions` result in `metrics.json` to see which catalog, rules and scoring were included.

**3. Change a synthetic observation.** In a separate copy, edit `backend/app/analytics/demo.py`: reduce the third-pick delay (`85+film`) by 20 seconds. Generate a *new* demo database in a different output directory. The co-lead median should move from 88.5 to 68.5 seconds; 7 of 12 drafts still release. Rebuilding a changed fixture into the original database intentionally rejects changed historical events. Do not present this exercise as an observed interface improvement.

**4. Test the real game on your machine.** Migrate to Phase 12. Export one in-progress practice film as `internal`, make another pick, then export again. Both imports must use the same session key, and only the new evidence should be added. Once released, replay the brief, export that separate film and verify the new start is `replay_start` and the original's output hash did not change. Try reading the original film's endpoint with a second account: no export should be returned. Repeat an exact replay request using the same owning session and original nonce: no second child should be created.

For a human playtest, agree on the observation period and capture procedure with participants first. Capture all starts that belong in your denominator, including incomplete films. Use owner-provided files with the explicit `playtest` classification. Record the catalog, rules, task, device class and any known idle intervals separately, without adding credentials to the analytics file. Inspect the resulting counts and describe what the data cannot answer.
